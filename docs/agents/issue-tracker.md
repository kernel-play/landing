# Issue Tracker

Work is tracked in Jira project `KAN` for now. This applies to this repository and the other kernel-play repositories; identify the affected repository in each ticket.

Before creating a ticket, search KAN for an existing issue covering the work. Read and update the existing issue when appropriate. Use Jira issue keys such as `KAN-606` when linking work, and preserve existing repository branch and commit conventions.

Use the connected Jira tools, or the team's configured Jira workflow, to read and write issues. Jira site URL, credentials, required fields, issue types, and status transitions are not defined here: resolve them from the connected project and existing tickets. If access or a required project detail is unavailable, ask for that detail before the dependent operation.

For new tickets, include the problem, affected repository, expected behavior, and acceptance criteria. Apply triage labels using `docs/agents/triage-labels.md`; labels do not imply Jira status transitions.

This configuration takes precedence over older references to GitHub Issues for tracking work, including infrastructure requests. Existing repository restrictions on implementation and deployment still apply.

If the team changes trackers later, update this file and the Issue tracker summary in the repository instruction file together. Do not create parallel GitHub or local markdown tickets unless the user requests them.
